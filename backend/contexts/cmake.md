## vcpkg — manifest mode

`vcpkg.json` at the project root puts vcpkg in **manifest mode**: every
dependency is declared in that file, vcpkg installs into `build/<preset>/vcpkg_installed/`,
and nothing is installed globally. This gives per-project, reproducible deps.

Installed packages:
- `crow 1.3.2` — HTTP framework (header-only, brings in `asio`)
- `nlohmann-json 3.12.0` — JSON (header-only)
- `libpqxx 8.0.1` — PostgreSQL C++ client (depends on `libpq 18.3`)
- `catch2 3.14.0` — test framework (wired up in a later conversation)

vcpkg is at `/opt/vcpkg` inside the container (`VCPKG_ROOT=/opt/vcpkg`).
The toolchain file is `/opt/vcpkg/scripts/buildsystems/vcpkg.cmake` — this is
how CMake discovers vcpkg-installed packages.

## CMake design decisions

### Target-based, not global
All compile flags use `target_compile_options(...PRIVATE ...)`, not
`add_compile_options()`. `PRIVATE` means the flags stay on this target and
don't leak to anything that links against it — good habit even for executables.

### `find_package` with CONFIG mode
Every `find_package` uses the `CONFIG` keyword:
```cmake
find_package(Crow CONFIG REQUIRED)
```
`CONFIG` tells CMake to look for the package's own `CrowConfig.cmake` (written
by vcpkg) rather than CMake's built-in `FindCrow.cmake` Find module. vcpkg
packages always provide CONFIG files — never use MODULE mode with vcpkg.

### CMake targets consumed
```
Crow::Crow
nlohmann_json::nlohmann_json
libpqxx::pqxx
```

### Sanitizers via option
```cmake
option(ENABLE_SANITIZERS "Enable ASan + UBSan" OFF)
```
The `dev` preset sets `ENABLE_SANITIZERS=ON` via `cacheVariables`. This keeps
the CMakeLists.txt clean and avoids hardcoding dev-only flags in the main build
definition.

## CMakePresets.json

Version 6 presets. A hidden `base` preset holds shared config (Ninja generator,
vcpkg toolchain). `dev` and `ci` inherit from it:

| Preset | Build type | Sanitizers | Binary dir |
|---|---|---|---|
| `dev` | Debug | ASan + UBSan | `build/dev/` |
| `ci` | Release | off | `build/ci/` |

Both `configurePresets` and `buildPresets` are defined so you can use
`cmake --build --preset=dev` (no need to `cd build/dev && ninja`).

## .clang-format

```yaml
BasedOnStyle: Google
IndentWidth: 4
ColumnLimit: 100
AccessModifierOffset: -4
SortIncludes: true
```

Run: `clang-format -i src/**/*.cpp src/**/*.hpp`

---

## .clang-tidy

`HeaderFilterRegex: src/.*` limits linting to project headers only (prevents
false positives from Crow/vcpkg internals). `WarningsAsErrors: "*"` treats all
enabled checks as errors.

Run: `clang-tidy -p build/dev src/app.cpp src/main.cpp`
(requires `compile_commands.json`, generated by `CMAKE_EXPORT_COMPILE_COMMANDS=ON`)

These were added to `Dockerfile.dev` after being discovered missing during

```bash
docker compose build backend
```

## app.cpp / main.cpp split — why

`main.cpp` only creates the Crow app and calls `setup_routes`. All route logic
lives in `app.cpp`. This means tests can `#include "app.hpp"` and call
`setup_routes` on a test app instance without going through `main`. This
pattern makes the HTTP layer unit-testable with Catch2 (planned for a later
conversation).
